# プレビューと一枚生成の既定条件を注文で置き換える

## 判定

プレビュー、キャラクターからの一枚生成、画風からの一枚生成で、確定した構図と固定否定が衝突する問題を修理した。プレビューの被写体・背景も、明示した特徴があれば既定値を重ねない。注文なしの生成文・除外文とLoRAは維持した。

人間の参考画像を使った実エージェントの応答では、2枚目の顔・髪・衣装、正面と背面の横並び、灰色背景が今回限定の条件になった。生成文の計算結果に白背景や視線の固定、複数方向を禁じる除外が残らないことを確認した。[参考画像・全応答・生成文](http://192.168.1.2:8766/api/file?path=/app/intent-generation-defaults-20260905.html)を閲覧できる。

今回の修正後のGPU画像確認は未実行。人間の画質まで合格したという判定ではない。本番機能配備、再学習、既存台帳の変更も行っていない。

## 原因と変更

開始HEADはc34ce60。引継ぎ時の変更はこの修理の3製品ファイルと新試験に限定されていた。直前の人間を優先する方針への返答は会話であり、進捗には数えない。継続時は同じ実解釈の実行ハンドルを読み、終了コード0を回収した。解釈を再起動していない。

- `backend/intent.py`: 構図の除外を既定条件として定義し、特徴単位の確定条件で置き換えた後に除外文を作る。画質に関する除外は保持する。
- `backend/services.py`: 3つの入口で同じ除外文の組立てを使う。プレビューの被写体と背景は、明示条件がある時には既定値を足さない。
- `backend/intent_service.py`: 解釈エージェントへ、その工程が付ける構図の除外と、プレビューの被写体・背景を見せる。工程の既定値を台帳の共通条件へ保存しない。
- `tests/test_generation_composition_negative.py`: 3入口それぞれの注文あり・なしを、確定操作、実際のサービス、模擬ComfyUIに送られるグラフ、台帳まで確認する。
- `render_reference_probe.py`: 既存の閲覧用組立てにプレビューと一枚生成を追加。製品の共通関数を利用し、採用を仮定した計算であることを明記する。

語句の置換表、特定のキャラクター・衣装・画像番号の分岐、モデル・LoRAの切替は追加していない。既存の英語自由入力は従来のままで、自由文を単語で分解して構図の意味を推測しない。
