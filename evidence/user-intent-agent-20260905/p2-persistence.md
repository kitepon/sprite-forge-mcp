# 非同期処理中のコメント保存を保持する修理

2026-09-05。対象はSprite Forgeの保存処理だけ。本番・実画像・GPU・モデル呼出しには触れていない。

## 再現と変更

学習・設定画生成の3件に加え、画像追加2経路と描き直し2条件を再現した。修正前は7件とも、途中に保存した新しい説明と完了後の説明の比較で失敗した。セットアップの失敗ではない。

`backend/services.py` の6経路を変更した。画像の取得後、学習・生成の完了後に最新台帳を読み直す。同期的な保存までの間にはawaitを挟まない。

| 経路 | 完了時に変える項目 | 保持するもの |
| --- | --- | --- |
| キャラクター／画風の画像追加 | samplesへの追加 | 取得待ち中に保存した既存画像の説明 |
| キャラクター／画風の学習 | lora_name・train_job・steps | 新しい説明とその他の台帳項目 |
| 設定画生成 | bible | 説明とパネル修正など |
| パネル描き直し | 対象panel_overrides、同じ設定画のat | 別パネルの修正、説明、途中で完成した別設定画の全項目 |

学習教材の説明は開始時の内容のまま。途中のコメント変更で学習済みの内容まで変わったと表示しない。画像取得前の台帳存在確認を維持し、存在しない台帳に画像取得を始める挙動へ変えない。

## 独立反証

親は実装担当、読み取り専用の子 `/root/comment_persistence_review` は反証担当とした。nativeのrefuter役指定は利用不可だったため、その失敗を伝え、同じ指定モデル・effort（Sol high）を通常の子として使用した。モデルや課金経路を黙って変えていない。子はファイルを変更していない。

反証で確認した2点を採用した。画像追加では取得前の存在確認を維持する。描き直しでは別設定画のjob_idだけでなく、panels_dir・sheet_path・html_pathも変えた試験を使い、最新bible全体が完全一致で残ることを確認する。子は最終差分を読み、今回の6経路に確実な欠陥・互換性破壊は見つからないと報告した。親も差分と下記実行結果を確認し、この保存修理を受け入れた。

## 実行結果

Python 3.14のローカル環境、一時台帳、疑似SSH／ComfyUIを使用。

- 修正前: `PYTHONPATH=. uv run pytest tests/test_comment_lifecycle.py -q --tb=short` → 7 failed（すべてコメントの最終比較）。
- 修正直後: 同じfocused test → 7 passed、0.23秒。
- 置換設定画のパス確認を加えた関連試験: `PYTHONPATH=. uv run pytest tests/test_comment_lifecycle.py tests/test_bible.py tests/test_style.py -q --tb=short` → 45 passed、3.45秒。
- 最終確認1回: `PYTHONPATH=. uv run pytest -q --tb=short` → 78 passed、4.16秒。既存Starlette／AnyIOの非推奨警告1件。
- `git diff --check` → 成功。

最終確認前に個別・関連試験を済ませた。WebUIを変更していないため、この単位ではブラウザー試験・JS再試験を実施していない。本番Python 3.13での配備試験、実機学習、生成画像の効果確認は未実施。
