# 構図の除外をパネルの条件へ移す

## 判定

設定画パネルの固定否定と、利用者が指定した構図の衝突を修理した。共通には画質の否定だけを残し、構図の除外は各パネルのcompositionが持つ。利用者が構図を変更した場合は、その構図の除外条件も通常の特徴更新で置き換わる。単語やキャラクター名による判定を加えていない。

旧来の23項目には同じ構図除外を持たせ、全項目の生成文・除外文を維持した。元から固定されていた23項目の生成文・サイズ等のSHA-256試験も、期待値を変更せず成功。明示した被写体や背景に既定の単独人物・白背景を重ねないことも確認した。

[比較ページ](http://192.168.1.2:8766/api/file?path=/app/intent-panel-negative-20260905.html)には比較元2枚と新規3枚を掲載。単独の正面・側面を維持し、指定した比較図は左に正面、右に背面になった。人物の主な特徴と塗りも保った。衣装の細部と配色、側面の左右の未達は残り、画像品質全体の合格ではない。

## コードと最小再現

開始HEADは1fec95a、作業ツリーclean。前単位は構成指示の修理と、固定否定の衝突を実際の生成文で確認した進捗。

- `backend/bible.py`: 画質否定と単独構図の否定を分ける。既定Panelは構図否定をnegative_partsに持ち、明示したパネルの被写体・背景を既定値で重複させない。既存のNEGATIVE定数は他の生成入口との互換のため同じ内容を保つ。
- `backend/panel_intent.py`: パネル条件と保存済み修正から否定文を組み立てる。条件の更新を伴わない経路でもパネルの否定を落とさず、元の肯定文の順序を保つ。
- `backend/sheet_layout.py`: 既定を編集用構成にする際、構図否定を該当partへ載せる。同じ特徴が複数の断片に分かれていても否定を重複しない。
- `tests/test_panel_composition_negative.py`: 指定した二方向を一律に否定しないこと、全23項目の旧出力、構図の否定置換と他の除外の保持、明示した被写体・背景の維持を確認する。

製品修理前に新しい4試験を実行し、固定否定が残る2試験の失敗を再現した。修理後は4件成功（0.06秒）、関連72件成功（3.67秒）。全試験で「全特徴の除外欄は空」という旧保存形式の期待1件が失敗したため、`test_panel_defaults.py`を構図欄への移動を確認する期待へ変更した。生成文を固定するSHA-256の期待は変更していない。該当3件成功（0.07秒）後、最終全Python 220件成功（6.86秒）、既存依存の非推奨警告1件。

公開APIやモデル・LoRA・解釈schemaは変更していない。単独構図を希望する既定と、利用者が明示的に保存した構成の除外条件を区別する。すでに保存されているカスタム構成に、記録されていない構図否定を補う移行は行わない。

## 残り

今回の修理は設定画パネルの範囲。`backend/services.py`のプレビュー・画風プレビュー・一枚生成は引き続き従来のNEGATIVEを使っており、そこでも構図の注文と固定除外が衝突する可能性がある。次に各入口で最小再現し、確認済み条件との組み立てを揃える。未検証の入口へ今回の成功を一般化しない。

カスタム構成を確定した実際のアプリ操作からの生成、本番CLI接続、画風変更、画像品質の残りは計画に保持する。人間を主な受入とし、人外の補助事例のために品質を落とさない。全体ゴールは未完了で、オーナーの裁定待ちはない。
