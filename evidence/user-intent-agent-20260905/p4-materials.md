## 実モデルによる観察

正式なCodex CLIのChatGPTログイン、gpt-5.6-terra、mediumで実行。追加課金・APIキー・Sonnet・リセットは使用していない。

入力はベルの4画像と「今後は4枚目の上下が分かれた衣装を強く採用してほしい。トップの色は青にしてほしい。教材の説明は、各画像に実際に写っている内容で作って。」。解釈は36.06秒で完了し、4画像すべてに英文が返った。白い衣装の観察と、トップを青へ変える希望が分かれていた。4枚目の上下セパレートと見える腹部も説明に含まれた。

ただし1枚目を右向きと誤読した。実画像と照合し、画面で日本語の「右向き」を「左向き」、英文の`facing right`を`facing left`へ訂正して観察だけを採用した。モデル原案は変更せず保存している。この1回の成功を新しい教材説明全般の無誤謬性とは扱わない。

最初の実CLIは失敗理由を標準エラーだけから返し、原因が見えなかった。構造化イベントのエラーも読むようにして、次の実行で`invalid_json_schema`（`caption_en`がrequiredにない）を確認した。旧保存形式で省略可能とした項目を、CLI用schemaだけ必須化して解決。失敗2回も削除していない。

保存先は本ディレクトリ配下のgit除外領域:

- `private/p4-materials/`・`private/p4-materials-diagnostic/`: 失敗記録。
- `private/p4-materials-v2/interpretation.json`: 修理後の実CLI応答と呼出し情報。
- `private/p4-ui/`: 同じ画像順へ対応付けた隔離台帳、画面で採用した観察、教材の写しと模擬学習job。
- 模擬完了job: `27983050-836d-404c-bc3d-b469c06a0af3`。観察の解釈job: `ba78f684-de14-474b-ace5-f4cb211b2c61`。希望は未採用のまま教材確認・模擬学習が成立した。

## ブラウザーと最終反証

ローカル隔離サーバーで実モデル応答を再現し、画像1の向きを訂正、観察だけ採用、全4教材を表示、再読み込み、模擬学習を開始、完了後に再読み込みして現在LoRAの教材履歴を確認した。学習の模擬処理は`_execute_training`を差し替え、SSH・GPU・実学習器を一切呼ばない。

390px幅では当初2列の教材説明が読みにくかったため、教材確認部分を1列へ変更。4画像の読み込み成功、カード幅271px、横はみ出しなしをDOMと画像で確認した。確認待ちの教材を作り直し、制作状況の「未完了・応答待ち」に表示され、完了class・稼働アニメーション・経過時間がないことも確認した。

独立した読取り専用検証者から2点の指摘を受けた。

1. 希望と観察を両方訂正した後、一方の採用による再描画でもう一方の未採用編集が消える。両順序のfocused testで再現し、再描画へ編集値を渡して修理。両方の値の保存まで試験。
2. 教材確認待ちを完了checkで表示し、未完了一覧から除外する。実DOMのfocused testで再現し、静止した確認待ち表示と一覧への残留を実装。実ブラウザーでも確認。

修理後の独立レビューは、今回の受入を妨げる再現可能な欠陥なし。原文・観察の分離、全教材の確認、写しの実行、二重開始拒否、最新台帳保持、既存job追跡、旧履歴の表示をコードで確認した。検証者は試験・モデル・GPU・ファイル変更を実行していない。

最終確認はローカルPython 3.14.7で`PYTHONPATH=. uv run pytest`: **119 passed、4.29秒**。既存のStarlette由来の非推奨警告1件。`node --test tests/*.test.mjs`: **17 passed**。`git diff --check`成功。全試験は個別確認後に1回だけ実行した。本番Python 3.13での最終実行は本番配備工程に残る。
