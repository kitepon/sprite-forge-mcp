# 制作の導線の整理 — 2026-09-06

## 変更

- 参考画像は選択後に自動追加する。失敗分だけ再送でき、保存前に次へ進まない。
- 画像ごとの希望と全体の希望は自動保存する。
- 学習は `start_learning` 一回で画像読取り・教材準備・学習まで進む。希望の解釈や質問がある場合だけ確認を表示し、`confirm_learning` で希望と画像説明を採用して学習する。
- 教材の説明へ希望を転記しない。生成時の共通条件と、実際に画像に見える観察は分けて保存する。
- 未学習・追加中の次工程は無効にし、理由をボタンのそばに表示する。
- プレビューと設定画全体の調整は任意の折りたたみに移す。設定画の細かい手動編集は折りたたみ、項目の一覧と日本語による変更希望を見せる。
- 学習済み画面では再学習を折りたたみ、プレビューへの案内を残す。

## 確認

Python 266 件、WebUI 40 件を確認した。個別試験の後、全試験を一回実行。

ブラウザーは幅390pxで次を操作した。

- 4枚の選択→自動追加→画像2の希望入力→全体の希望入力→学習へ移動。
- 保存された画像数、画像2の希望、全体の希望が学習画面でも一致。
- 読取り中の再読み込み後も確認案を表示。一度の確認で学習し、完了後に次工程を有効化。
- 画風の新規学習では、質問・変更案がない場合、開始ボタン一回で完了。
- 追加に失敗した画像は失敗表示と取り消し操作を表示。単体試験では成功済み画像を重複追加せず残りだけを再送。
- プレビュー・設定画の通常表示で専門入力を非表示。設定画の手動編集カードは0件表示、項目名の一覧は表示。
- 各確認画面で横方向のはみ出しなし。

画像解析とGPU実行は `fixture_app.py` で模擬した。HTTP、アップロード、台帳、説明の採用、教材の固定、工程遷移は製品実装を使った。本番の画像・LoRAを使った再学習や、生成画質の再評価は行っていない。

## 試験用サーバー

リポジトリ直下で、一時データ用のディレクトリを指定して起動する。本番データを指定しない。

```sh
SPRITE_FLOW_TEST_CACHE=$(mktemp -d /tmp/sprite-flow-ux.XXXXXX)
SPRITEFORGE_CACHE="$SPRITE_FLOW_TEST_CACHE" uv run uvicorn evidence.web-flow-20260906.fixture_app:app --host 127.0.0.1 --port 8773
```

バックグラウンドの検証ブラウザーで描画フレームが停止した場合は、Chromeのフォーカスエミュレーションで描画を再開してから操作する。クリックの強制実行を動作確認の代わりにしていない。
