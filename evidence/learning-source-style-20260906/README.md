# 素材から学ぶ画風と、生成時の別画風選択を分離

## 修正した原因

学習前の画風への希望にも、生成用の「登録済み画風LoRAを選ぶ」規約を適用していた。未登録の素材画風を指定すると、画風が未解決として学習開始を止めていた。チェックの言い換えでは解消しなかった。

学習前は、各画像を優先教材・通常教材・参考のみへ振り分ける。希望と画像の観察を分けたまま、前二者だけを学習器へ渡す。優先教材の使用頻度は通常の2倍、全体の学習ステップ数は変えない。同じ優先度の画像は同じ頻度になる。別の画風LoRAを重ねる操作は生成工程に残す。

既存の [sd-scriptsのデータセット設定](https://github.com/kohya-ss/sd-scripts/blob/main/docs/config_README-ja.md) にある subsets / num_repeats を使用した。新しい学習器・LoRAの追加方式・特徴別の分離学習は導入していない。2倍は優先度を区別する初期設定であり、品質上の最適値と評価したものではない。

## 確認済み

- Python 274件、WebUI 41件の全試験に成功。その後、開始応答待ちに旧記録を見せる表示も修正し、対応するWebUI試験を1件追加。関連6件に成功。
- 教材の画像バイトが元画像と一致すること、参考のみの画像が教材に入らないこと、優先教材と通常教材の使用回数が2:1であることを試験した。
- 画像の追加・変更・画像別コメント・全体希望の更新後には、保存済みの古い採用方針を使わないことを確認した。
- スマホ幅390pxで、素材画風の解釈→一度の確認→教材保存と模擬学習→プレビューへの遷移を操作した。画風選択・希望放棄チェックはなく、横方向のはみ出しもない。
- 旧形式の確認待ちでは、保存済み希望と「学習を始める」を表示し、再解釈から続けられることをブラウザーと単体試験で確認した。
- 実物の6枚と保存済みの注文を、独立した検証台帳で公式Codex CLIへ渡した。ChatGPTの契約ログイン、gpt-5.6-terra、64.25秒。画像1はポーズ・構図の参考のみ、画像2は衣装・体形、画像3〜6は画風の教材という提案になった。登録済み画風の選択・希望放棄・不要な追加質問はなかった。画像2〜6はいずれも優先指定で、教材内では同じ頻度となる。
- GPU実機で教材5枚、1epoch 200例、全1,200ステップとして読み込まれ、学習が進むことまで確認した。

## 実機検証の再開

`probe.py` は本番を読み取り、指定した出力先に検証専用の画像・台帳・記録を作る。学習先は製品の通常設定を使い、検証用LoRA名で保存する。本番のキャラクターは変更しない。画像・LoRA・個人用の結果はcommitしない。

現在の検証はローカルの `.cache/learning-source-style-20260906/`。学習プロセスはAitermの `sprite-learning-probe` で実行中。次の呼び出しでその完了結果を確認し、完了後だけ同じ出力先に `probe.py preview` を実行する。生成seedは42。

```sh
PYTHONPATH=. uv run python evidence/learning-source-style-20260906/probe.py preview --output .cache/learning-source-style-20260906
```

Mac上での学習検証は、同じfoxを指すSSH登録名 `windows-workstation` を `SPRITEFORGE_BOX_SSH` へ指定した。本番の接続名と設定は変更していない。
