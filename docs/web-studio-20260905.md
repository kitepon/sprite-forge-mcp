# WebUI 全面刷新

既存の五つの制作コースと、サンプル・学習・確認を分ける方針を維持する。
画像を中心に、明るい紙色と深緑の制作スタジオへ改める。

## 実装と受入

- ホームから目的を選び、画像カードでキャラクター・画風を選択する。
- 各工程で戻れる。学習・生成はボタンで明示的に開始する。
- 画像追加前に各画像と説明を確認する。保存・削除で他画像の下書きを消さない。
- 画像の縦横比を保持し、拡大・ダウンロードを提供する。
- 待機中も前の成果物と入力を残す。実際の学習 step・完成パネル数を表示し、架空の残り時間を出さない。
- 画面移動後も処理状況と結果をたどれる。通信エラーと生成失敗を区別する。
- 履歴を画像のギャラリーにする。手動のパス・ジョブ番号入力を通常導線から外す。
- 通常幅・スマートフォン幅で四枚追加、説明保存、削除後の追加、工程移動、生成進捗、失敗表示を確認する。
- 本番データや GPU をテスト教材にしない。生成ワークフロー・モデルは変更しない。

進捗表示のために既存ジョブへ時刻・途中画像を保存し、画風サンプルの説明変更と削除も共通サービスから公開する。

## 実装した内容

明るい紙色・深緑のスタジオ、実際の参考画像を使うホーム、目的別の五つのコース、画像カードの選択、各工程の前後移動、作品ギャラリー、制作状況、道具箱へ刷新した。スマートフォンは下部ナビゲーションを使う。

サンプル追加は選択中の画像ごとに説明を付け、転送と台帳への追加を表示する。保存前の説明は画像の対応を保って端末に残す。削除後の追加が残存画像を上書きしていた採番も修正した。画風の説明保存と画像削除を REST/MCP 共通のサービスに追加した。

制作は既存の POST とジョブ記録を使う。開始直前の記録を基準に、新しい該当ジョブが一件に定まる場合だけ追跡する。曖昧な場合は特定の進捗を自分のものと表示しない。進捗は保存された実測 step・完成画像数を 2.5 秒ごとに取得する。再読み込み後は保存済みのジョブ番号から確認し、POST を再送しない。古い未完了記録は自動で失敗・成功に変更せず、最後の報告として表示する。

生成の途中画像・ジョブ時刻を保存し、学習の失敗も記録へ残す。設定画の描き直しでは表示更新用の時刻を更新する。旧ブラウザーキャッシュとの混在で初期化できない状態が実際に出たため、ビルド不要の ESM に版付き URL と再取得設定を付けた。

## ブラウザーで確認済み

試験用サーバーは `tests/studio_fixture.py`。本番の参考画像を読み取り専用で複製して表示確認に使用し、変更は新規の一時ディレクトリだけへ保存した。GPU は fixture であり、今回、実機で新たな生成・学習は行っていない。

- 通常幅と 390px 幅のホーム・参考画像カードを目視。縦長、横長、設定画を含む画像の縦横比を保持。
- キャラクター選択、参考画像、設定画、描画コース間の移動。
- 別の画像の説明保存後も、未保存の説明を保持。
- 中間の画像を削除した後、四枚を一度に選び、それぞれ異なる説明を付けて追加。残存三枚と追加四枚が保存され、区切り記号を含む説明も欠けないことを確認。
- 再読み込み後、七枚の画像・保存済み説明・元画像の未保存下書きを確認。
- 設定画の生成を開始して制作状況へ移動。実測 0/23 の表示から完成し、工程へ戻って 23/23 と設定画を確認。
- 描画失敗時に元の入力と失敗理由を保持。内容を変更した次の生成は完了し、画像を表示。

内蔵ブラウザーの旧 native confirm が自動操作を止めたため、確認 UI を通常の画面内ダイアログへ変更し、操作試験は Chrome のネイティブ操作で続行した。

全試験は Python 71 件、JavaScript 7 件が成功。差分の空白検査と JavaScript 構文検査も成功した。
