# 画像生成の修正（2026-09-05）

対象は、生成ロジックの確認で再現した次の3件。モデル、プロンプト、学習条件は変更しない。

## 設定画の再生成

従来は新しい生成を始める前に、現在のパネルとその修正履歴を削除していた。パネル生成・PNG合成・HTML作成の途中で失敗すると、台帳が指す旧版の実体が失われていた。

既存のジョブIDを使って `characters/<key>/bible/<job_id>/panels/` と `generated/bible_<key>_<job_id>.png` / `.html` に生成し、完成してからキャラクター台帳の参照先を更新する。旧版と修正履歴は残す。失敗時にできた部分画像もそのジョブの保存先へ残り、現行版にはならない。

単一パネルの描き直しは台帳の `sheet_path` / `html_path` を更新する。旧形式の設定画も、そのまま描き直せる。固定名の出力を推測せず、APIが返すパスを利用する。

## 選択した画風のプレビュー

画面は選んだ画風を渡していたが、`web/api.js` の `previewCharacter` が受け取らず捨てていた。画風の引数を REST へ転送する。キャラクターに画風を固定する前でも、選択した LoRA を重ねて試せる。

## 生成失敗の記録

キャラクターの新規画像、プレビュー、画風のみの生成、img2img、単一パネルの描き直し、スプライト生成は、例外時に状態と理由をジョブとイベントへ保存し、元の例外を呼出元へ返す。再試行や代替モデルへの切替は追加しない。設定画全体の生成が既に持つ失敗記録は維持する。

## 検証

- 修正前に、旧版の消失、画風引数の欠落、失敗後に待機中・実行中が残ることを再現。
- 修正後は、再生成途中の失敗でも旧23パネル・PNG・HTML・修正履歴と台帳が変わらないことを確認。
- 再生成成功後の参照先更新、現行版の描き直し、旧保存形式での描き直しを確認。
- 6生成経路について、送信・完了待ち・取得・保存段階の例外で失敗状態とイベントが残り、例外も返ることを確認。
- 全Python試験65件、WebUI API試験1件が成功。
- ローカルの実ブラウザーで画風を選んで2枚のプレビューを表示。RESTを通じてキャラクターと選択した画風の両LoRAがサービスへ渡ったことを確認。GPU応答はfixtureで置換し、コンソールエラーは0件。
