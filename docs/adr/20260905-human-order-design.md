# 人間の顔・表情・基本衣装を保つ注文解釈

開始点6405a99。前単位は候補の実測と不採用判定を完了した進捗。人間の受入を優先する既存裁定と、対象別案で明示注文を届ける独立反証済みの契約を維持する。同じ生成側の優先順を使い、schema・保存方式は変更しない。

親が既存候補の不足2点を修理する。顔立ちの維持に口の開閉など表情を固定する情報を含めないこと、今後の共通条件は対象別の保存案とは別に残すことを明記する。対象別の案は注文の意味に合うものに限り、別衣装と単品への無差別適用を行わない。今回限りの希望は共通保存へ入れない。

直前の関連40件成功をベースラインとし、顔・表情と共通・個別保存の契約をfocused testで固定する。製品指示の候補を同じ人間画像・同じ原文へ各1回適用し、全応答と現在の生成文を確認する。人間が成立してからスライムを補助確認する。必要な修正で入力を変える場合は比較条件の変更として記録する。モデル呼出しの失敗を再試行しない。画像効果は別の確認として扱う。

書込みは親のみ。同じ指示文と実測結果が連鎖するため委譲しない。正式CLIの既存契約認証・モデルを維持し、追加課金・APIキー・リセット・Sonnet・学習は使わない。本単位では機能本体の本番配備をしない。人間で問題が残れば採用済みに見せず、原因と候補を記録する。
