# コメントの提案・確認・採用の契約

2026-09-05。ユーザーの自律遂行指示に基づきP2を続ける。P2から生成比較の受入へ連鎖するため統括レーンとし、親が公開API・台帳・モデル接続のFを担当する。書込みは並行させず、独立した読み取り反証を同時に行う。

コメントは既存のjob_idを持つ解釈ジョブとして、モデル呼出し前に保存する。原文、工程、所有するキャラクター／画風、注文時の画像順と既存key・index・path、当時の共通条件を残す。失敗しても原文と失敗理由を残す。モデル出力は未確定の提案とし、確認した変更項目だけを採用する。新しい全体ID体系や配送キューは作らない。

台帳の共通条件は特徴別に保存する。今回限定とパネル限定は共通条件へ自動昇格させない。観察結果と制作の希望は別項目。確定時は最新台帳の無関係な特徴を保つ。提案後に同じ特徴が変更されていた場合は勝手に上書きせず、読み直すよう明示する。確定した生成条件の全文をジョブにも残し、実行との対応に既存job_idを使う。

参照の再利用を防ぐため、既存sample indexの次の値を台帳に保存する。旧台帳は既存最大indexから導出し、削除時も減らさない。これは既存番号の採番修理であり、新しい識別体系ではない。削除した画像への参照を別画像へ付け替えず、未確定案を採用する時に参照画像が存在しなければ明示的に止める。

モデルは正式なCodex CLIのChatGPTログインでTerraを呼ぶ。ユーザー設定・文書・shell・web・子の呼出しを無効にし、添付画像と入力だけを読む。モデル出力は構造化して境界で検査する。API認証・追加利用・失敗時の別モデル・再試行は使わない。

本番のコンテナとホストCLIの接続は、既存SSHを使い、Sprite Forgeの一回の実行入口へ入力を渡す案を検証する。認証ファイルのコピーやマウントはしない。接続設定は製品の配備設定が持ち、モデルにshell手順を選ばせない。構築には公式OpenAI文書と正式CLIの実測を用いる。

WebUIは各工程に注文欄・原文の保存状態・解釈中・確認待ち・確定済みを表示する。画像の説明の下書きは工程移動と実行前に保存する。訂正は原文を編集して再解釈するか、提案された生成文を編集して採用する。画像の採用合否や架空の進捗率は追加しない。

受入は一時台帳での保存／失敗／参照／範囲の試験、公式CLIの画像付き実行、実ブラウザーの入力・保存・訂正・再表示、関連試験の順。全試験は変更機能の確認後に一度。P3の最初の4枚比較と、再学習の実行裁定は計画どおり後続に残す。
