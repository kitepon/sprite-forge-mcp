# 一枚生成へ確定した注文を渡す契約

2026-09-05。P5の最初の実装単位。設定画・パネル修正・画風変更の選択への接続は後続の単位で扱い、P5全体をこの単位へ縮小しない。

キャラクターの`generate_from_bible`と画風の`generate_image`へ、省略可能な`intent_job_id`を加える。同じ対象・drawing工程で確定した解釈だけを受け取り、共通条件と今回の注文を既存の特徴単位の解決処理で合成する。肯定文と否定文、解釈job、実際の生成条件を生成jobに残す。今回だけの条件は台帳の共通条件へ保存しない。

英語の自由入力は従来の入口として残す。確定した条件と自由入力を同時に使うと、衣装や向きの矛盾を単純連結するため、併用は明示エラーとする。注文を使う場合は自由入力を空欄とし、希望する場面・被写体も注文に含めて解釈する。内容のない一枚生成は開始しない。

WebUIは両方の一枚生成で解釈・訂正・採用を有効化し、生成開始前に原文を保存して、採用したjobをRESTへ渡す。キャラクター＋選択した画風と、画風だけの生成は分離したままとする。REST/MCPは同じサービスを公開し、生成器と学習器の責務を変更しない。

画風の特徴語を内容文へ混ぜることは許可しない。画風変更そのものをLoRAの選択・学習へ結び付ける後続実装は未完であり、既存の明示エラーを維持する。この単位で未接続の画風変更を採用済みにはしない。

親が公開契約・配線・試験を一括して書く。2経路は同じ解決処理とUIを共有するためwriterへ並列委譲しない。既存の読取り専用検証者が境界を反証する。

受入は両経路の肯定／否定文・台帳保存・対象や工程違いの拒否・未採用の拒否・自由入力の互換性・REST/MCPの配線・実ブラウザーの採用と再表示。実画像による効果確認と本番機能配備は後続の受入に残す。実機再学習、他の支払経路、Sonnet、固定の衣装語は対象外。
